PumpkinPie

A Minecraft 26.2 server written in Rust, built for vanilla behavioural parity.

Download Implementation tracker Source

What this is

PumpkinPie is a Minecraft: Java Edition server for 26.2. It began as a fork of Pumpkin and has grown into its own project with its own priority: matching what vanilla actually does. Every change is checked against a decompiled 26.2 server, and where it can be, confirmed against a running server with a real client attached rather than by reading code alone.

That is the difference in practice. Recent work fixed freezing damage applied five times over, fire resistance that ignored fireballs, hoppers running eleven percent slow, comparators reading the wrong signal from their side inputs, and a registry encoding that made strict clients refuse to join. Each fix cites the vanilla source it was checked against in the commit history.

Verify what you downloaded

Check the archive against the published checksum before running it:

sha256sum -c SHA256SUMS --ignore-missing
On virus scanners. These binaries are unsigned, so Windows SmartScreen and some antivirus products will warn about them — that is what an unsigned executable from a small project looks like, not evidence of anything in particular. Every release links a VirusTotal report for its archives so you can read the scan results yourself, and building from source is always available if you would rather not take a binary on trust.

Running it

tar xzf pumpkinpie-x86_64-unknown-linux-gnu.tar.gz
cd pumpkinpie
./pumpkin

The server writes pumpkin.toml on first start. It speaks the 26.2 protocol; older clients are not supported.

Read all three together. The third disagrees with the first two, and that is the interesting part. PumpkinPie covers the most of vanilla and matches the most methods outright. SteelMC matches a higher share of what it takes on, because it takes on less: its percentage is over 5418 methods where PumpkinPie's is over 8512. A project implementing fewer classes scores higher per class while covering less of the game, so no one number settles it. Against the upstream it forked from, PumpkinPie leads on every measure here.

Two caveats. The instrument carries 18 negative-control probes; only 9 apply to SteelMC, and upstream needed --no-probes because one failed against its layout, so cross-repo confidence is weaker than same-repo confidence. And this is name-level matching: it does not prove any of the three behaves correctly.

Parity

The implementation tracker shows which vanilla classes have an analogue here and how much of each one's surface is covered, measured against the decompile. It counts surface, not behaviour — a matched method can still behave differently, which is what the ongoing verification work is for.
